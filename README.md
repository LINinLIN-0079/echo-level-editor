# 残响回廊 · 关卡编辑器（Godot 4 编辑器插件）

一个给 2D 横版游戏用的 **Godot 4 编辑器插件**：把做关卡、调敌人 AI、编排过场动画全部放进
Godot 编辑器里，改完直接一键试玩，不需要在"外部工具"和"游戏"之间来回导数据。

> ⚠️ **重要前提（请先读）**：本插件是《残响回廊 Echo Corridor》项目**配套**的编辑器，
> 它的界面代码会直接调用该项目的核心脚本（见下面「前置依赖」）。
> **只把本插件放进一个空项目里是无法运行的** —— 必须同时具备那些核心类，
> 或按相同接口自行实现。这不是"配置问题"，是设计如此（编辑器与游戏共用同一套数据模型）。

---

## 功能一览

插件会在编辑器顶栏多加一页 **「残响关卡」**，内含 4 个页签：

### 1. 关卡编辑
- 画布工具：**画笔 / 矩形 / 敌人 / 选择 / 拾取物 / 触发器 / ✋平移**（工具条上分组显示，带快捷键 1~7）
- 平移有三种方式：`✋平移`工具左键拖动、中键拖动、空格+左键；另有**左键长按 0.3s 再拖 = 平移**（避免误画）
- 撤销 / 重做、**写盘前校验**（越界障碍、未知敌人类型、贴脸出生点、门指向不存在的房间等一律拦下）
- 保存是**原子写 + `.bak` 备份**，校验不过**拒绝写盘**（磁盘不会被写坏）
- 右侧检查器逐条编辑房间元数据（名称/金币/胜负条件/Boss 房/能力奖励…）
- **模板预制体**：把一段内容（障碍/敌人/拾取/触发器）存成模板，之后一键套用到别处

### 2. 敌人 AI
- 行为树编辑器：从 40 条动作目录里拼树，实时看当前执行到哪个叶子节点

### 3. 关卡图
- 按门做 BFS 的**可达性校验**：可达房间数、终点是否可达、有没有"永久过不去的门"，
  还能按"假定已获得的能力"（冲刺/二段跳）重新分析
- 问题清单可点击定位到具体房间/门

### 4. 过场动画（对齐剪映的操作习惯）
- 关键帧时间线：轨道行高可拖、**Ctrl+滚轮缩放 / 裸滚轮浏览**、右上角缩放控件带刻度、
  **缩放锚在鼠标处**
- 轨道里画**真实内容**：镜头/角色轨画真实数值轨迹、字幕轨显示字幕文字、
  特效轨画波形（**能读到真实音频文件时画真波形**，读不到才回退示意图并标注「（示意）」）
- **在预览画面里直接改镜头**：拖动=平移镜头、滚轮=缩放镜头（鼠标处为锚），
  满意后点「打关键帧」写进 camera 轨道（**一次操作 = 一步撤销**）
- 播放器窗口可以拉伸压缩（左右把手/数值框/预设），并提供比例、背景（黑/棋盘格）、安全框、全屏
- 舞台切换：在 camera 关键帧上写 `room`，预览与游戏会跟着换房间背景
- `spawn` 轨道：在过场里生成/销毁实体（伏击、开门放怪…）

### 其他
- **一键试玩回流**：从编辑器直接进游戏试玩"当前编辑的房"，试玩期间**不会写真实存档**，
  结束自动回到同一房（Ctrl+Alt+V）
- 素材库 / 属性检查器以**编辑器原生侧栏面板**形式停靠（可拖动、可浮动、可合并标签）
- 统一的**共享主题**（配色/圆角/按钮悬停按下/小标题层级）

## 安装

1. 把本仓库的 `addons/echo_level_editor/` 放进你的 Godot 4 项目根目录（最终形如
   `<你的项目>/addons/echo_level_editor/plugin.cfg`）
2. Godot → `项目 → 项目设置 → 插件` → 勾选 **Echo Level Editor** 启用
3. 顶栏会出现 **「残响关卡」** 页

## 快捷键

| 快捷键 | 作用 |
|---|---|
| `Ctrl+Alt+S` | 保存当前房间（**不要用 Ctrl+S**，那是编辑器本体的"保存场景"） |
| `Ctrl+Alt+R` | 重新载入 |
| `Ctrl+Alt+V` | 一键试玩 |
| `Ctrl+Z` | 撤销 |
| `1`~`7` | 切换画布工具 |
| `Shift+Z` | 过场：全局预览缩放 |
| `-` / `+` | 时间线缩放 |

## 前置依赖（**必须**在项目里存在）

本插件的界面与数据层直接引用下列类（括号内是本项目中的位置，仅供参考）：

| 类 | 用途 | 本项目位置 |
|---|---|---|
| `WorldDatabase` | 读取 `data/world.json` 与房间数据 | `core/level_data.gd` |
| `Cutscene` | 过场数据模型 / 采样 / 播放 | `core/cutscene.gd` |
| `Interactables` | 拾取物与触发器的解析、校验、运行时行为 | `core/interactables.gd` |
| `EnemyData` | 敌人规格（`data/enemies/*.tres`） | `core/enemy_data.gd` |
| `GameConstants` | 瓦片尺寸等常量 | `core/` |
| `TilePhysics` | AABB ↔ 瓦片碰撞查询 | `core/` |
| `VisualBinding` | 美术占位与资产绑定 | `core/visual_binding.gd` |
| `SceneRouter` / `SaveSystem` / `GameState` / `AudioManager` / `EventBus` | **仅**「一键试玩」与日志用到 | 项目 autoload |

数据文件约定（编辑器读写的就是这些）：

```
data/world.json            # 世界索引：30 个房间、门、存档点、传送
data/rooms/R01.json …      # 每间房：网格 / 障碍 / 敌人 / 门 / 拾取物 / 触发器
data/cutscenes/intro.json  # 过场：轨道 + 关键帧
data/ai/<type>.json        # 敌人行为树
```

## 已知限制（如实说明）

- **不能独立运行**：如上，依赖《残响回廊》的 core 类；若要在别的项目用，需要按相同接口实现
  或一并移植那些脚本。
- **特效轨真波形**：当项目里存在 `res://data/audio/sfx/<id>.tres` 或
  `res://assets/audio/sfx/<id>.wav` 时画真实峰值；否则显示**示意波形**并标注「（示意）」。
- 过场数据没有"舞台"字段时，预览会**按镜头位置推断房间**（这是兼容老数据的兜底行为）。
- 编辑器只在**编辑器进程**里存在：游戏导出版里没有任何插件代码（有测试守住这条）。
